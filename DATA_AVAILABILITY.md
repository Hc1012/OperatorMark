# Data availability and reproducibility boundary

The versioned asset `OperatorMark_1.0.0-rc5.zip` on [GitHub Releases](https://github.com/Hc1012/OperatorMark/releases) contains the complete compact **saved-result analysis** artifact. Extract it to obtain the `OperatorMark` folder. This front-page repository provides access and citation information; all file paths below refer to the extracted release archive. It makes the reported statistical decisions and figures reproducible without a GPU. It is not a complete distribution of all raw data or a claim of independent end-to-end replication.

| Available in the release archive | What it supports |
| --- | --- |
| 1,271 model observations with F/J/K/T/P256 where measured, score extrema, counts, domain and task status | Recompute model utility/detection decisions, owner ratios, cohort summaries and figures. |
| Qualification inputs, 1,240 B2 rows, 210 fixed null rows, native target-level results, API counts and adaptive readouts | Recompute the included aggregate decisions; inspect scoped supplemental outcomes. |
| Frozen analysis graph and original rule files | Inspect exactly which populations and rules the readout applies. |
| Frozen research source snapshot plus later campaign implementations | Inspect methods and numerical implementation without executing private launch infrastructure. |
| Separate historical outcomes and scope dispositions | Retain negative results and amendments without pooling incompatible studies. |
| Hash manifests and archive/member pointers | Trace compact observations to recorded original identities and detect accidental changes to this release. |

## Not distributed in the release archive

The large corpus/reference arrays, model checkpoints, teacher caches, full score grids, private defender keys/seeds, original raw returns and operational authorization records are not in the release archive. Account credentials, Drive object/folder identifiers, private conversations, billing records and the private repository history are also excluded. Source code may mention expected private filenames or generic Colab paths; those strings do not contain the underlying files or grant access.

Without those raw assets, a reader cannot independently re-evaluate the trained networks, re-hash every raw tensor, rerun the full teacher-query/training campaign, or establish chain of custody. Saved maxima are sufficient to reproduce the published detection decision, not to independently regenerate the underlying 4,096-score grid. The earlier adaptive grids were already absent from the compact review and are not newly claimed as verified here.

The frozen scientific graph preserves historical private-artifact hashes, relative archive/member names and deliberate null bindings. A hash is a content identifier, not a public download link, proof of exclusive possession, or evidence of when an experiment happened. `provenance/CLAIM_EVIDENCE_INDEX.json` distinguishes public analysis pointers from original private source pointers. The compact-input hashes remain identical to the completed private analysis.

No public raw-data hosting location, DOI, availability-on-request promise or future release date is invented. If a later paper or venue requires fuller raw-data reproducibility, a separately scoped data deposit would be needed; it must be described transparently rather than implied by this analysis package.

## Source and environment fidelity

The 338-file pinned research snapshot is preserved with three public-only path redactions in an archived handoff helper. The original agent instruction file is renamed to `ARCHIVED_AGENT_INSTRUCTIONS.txt` so its old phase directions are not treated as current project instructions. Every original and public source hash is recorded. The nine files used by the statistical replay are byte-identical to their frozen originals.

`environment/requirements-colab-historical.txt` is the retained historical package inventory, not an instruction to modify a current Colab runtime. The public analysis instead uses the small, separate `requirements-analysis.txt`. Exact raw-campaign reproducibility across current cloud images is neither tested nor promised.

`RELEASE_VALIDATION.json` preserves the original rc1 release checks. The prior rc2, rc3 and rc4 editorial records are preserved under `provenance/` as historical validation. The current `EDITORIAL_RELEASE_VALIDATION.json` records rc5 repository/publication-status alignment and byte-identity checks. Scientific inputs, code and the four reproducibility figures reuse the earlier replay. These records distinguish historical execution from editorial verification; they do not constitute a fresh scientific audit, new physical qualification, new engineering acceptance or clean-room training replication.
